## 設計決定

| 編號     | 決定                                                                                                                                                                                   | 類型                  | 為什麼                                                                                                                                                                                                                                                                                                                                                                                                                            | 出處                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| CONVO-1  | 讓消費端自組訊息列，做法是匯出有主題的內容元件（`BotMessageText`、`UserMessageText`），不加 `hideAvatar` 之類的開關 prop                                                               | PM 未定義、前端先決定 | 開關 prop 已被明確排除，方向是「讓消費端自己客製訊息」；外框 `TemplateBox` 本來就公開，缺的只是有主題的內容                                                                                                                                                                                                                                                                                                                       | 原 BUILD-026、BUILD-042                          |
| CONVO-5  | run 進行中指示線是 chat column grid 的獨立一列，畫在 footer slot 之前。不要把它搬回 `ChatbotFooter`；`RunningIndicator` 也不匯出。自訂 `renderFooter` 的消費端不要再畫自己的上緣分隔線 | 刻意的行為            | 它綁的是整條連線的狀態；放在 footer 裡會被 `renderFooter` 一起換掉（heimdall-pm#200）。指示線在所有 footer 路徑上都已出現，消費端不需要自己掛；消費端自己再畫一條分隔線，會和它疊成雙線                                                                                                                                                                                                                                           | 原 BUILD-034                                     |
| CONVO-8  | spinner 共用同一個相位：用 Web Animations API 並把 `startTime` 釘在 0。不要用 CSS animation，也不要在元件裡自己寫 spin `@keyframes`                                                    | 刻意的行為            | CSS animation 從各自掛載的那一刻起算，沒有共同的時間原點；滿畫面不同相位的 spinner 看起來像在扭動（BUG-007）。目前有一個例外沒有遵守，見 CONVO-37                                                                                                                                                                                                                                                                                 | 原 BUILD-050                                     |
| CONVO-9  | `prefers-reduced-motion` 時所有 spinner 一律停轉，包括原本只是減速的 chat header。不要把 chat header 改回減速                                                                          | 刻意的行為            | BUG-007 驗收標準第 3 條寫「停轉行為維持不變」，但七處裡只有 chat header 原本是減速；統一停轉後，PM 的回歸紀錄把它記為附帶修正並判 PASS（sdk-pm `docs/test-runs/2026-08-07-asgard-js-sdk-bug-007-spinner-regression.md:25`），只是 BUG-007 那句驗收標準的原文沒跟著改                                                                                                                                                              | 原 BUILD-050、REVIEW-050；PM 回歸紀錄 2026-08-07 |
| CONVO-13 | 已終態的 subagent 再收到 `subagentStart` 或子 tool-call 的 `toolStart`，狀態回到 `running`，並清掉上一次的 `summary`。不要把狀態改回「只會收斂」                                       | 刻意的行為            | 有新活動就是又在跑。核准：asgard-ai-platform/asgard-js-sdk#382（sdk-pm 主要作者 2026-08-05 留言要求保留）；PM 規格的措辭沒跟著改，見 CONVO-39。asgard-core#171（2026-08-05 合併）之後，後端在跨 turn 恢復時會補發 `subagent.start`／`subagent.complete`，這條成了後備：後端的 owner id 查詢是 best-effort，查不到時 lifecycle event 仍會被丟掉，只剩子 tool-call 能讓卡片顯示仍在活動。消費端因此不能把「出現終態」當成一次性事件 | 原 BUILD-041                                     |
| CONVO-15 | subagent 的子 tool-call 結果原樣交出，不截斷、不遮蔽；欄位名跟 `ConversationToolCallMessage` 一致（`result`／`sidecar`），不跟 wire 名                                                 | 理由                  | 遮蔽與截斷已裁決歸呈現端；同一個值在兩個 SDK 型別上叫兩個名字，會讓人以為是兩種東西                                                                                                                                                                                                                                                                                                                                               | 原 BUILD-083                                     |
| CONVO-36 | 使用者泡泡的 `max-width: 75%` 留在 `.text--user`；機器人那邊的寬度則放在 `.text--bot-default`。兩邊刻意不對稱，不要「對齊」                                                            | 刻意的行為            | 機器人的上限移出去，是為了讓自組的機器人列填滿閱讀寬度；使用者那邊的 75% 是泡泡外觀的一部分，自組的使用者列也該是泡泡。要改寬度用 `className`                                                                                                                                                                                                                                                                                     | 原 BUILD-042                                     |
| CONVO-38 | 錯誤泡泡與思考區塊的「顯示詳情」鈕只在展開時帶 `aria-controls`；收合時內容區塊直接移除，不用 `hidden` 藏著                                                                             | 理由                  | 收合時指向不存在的 id 是懸空的 IDREF，比不帶更糟。捨棄的方案是詳情區塊一律掛上、收合時用 `hidden` 藏起來，這樣 `aria-controls` 可以無條件帶，但對話裡每個錯誤泡泡都要先掛一份 JSON，不管有沒有人打開                                                                                                                                                                                                                              | 原 REVIEW-063                                    |

| CONVO-27 | 重播出的 tool-call 時間是「現在」，不是原始時間                             | 跨 rejoin 以 `time` 排序不準；畫面依串流順序與 `${processId}-${callSeq}` 排列，目前看不出差異；需要依時間排序時再處理                                                                                                                                                                                                                                 | 不處理   |
