## 設計決定

| 編號     | 決定                                                                                                                                                                                   | 類型                  | 為什麼                                                                                                                                                                                  | 出處                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| CONVO-1  | 讓消費端自組訊息列，做法是匯出有主題的內容元件（`BotMessageText`、`UserMessageText`），不加 `hideAvatar` 之類的開關 prop                                                               | PM 未定義、前端先決定 | 開關 prop 已被明確排除，方向是「讓消費端自己客製訊息」；外框 `TemplateBox` 本來就公開，缺的只是有主題的內容                                                                             | 原 BUILD-026、BUILD-042  |
| CONVO-5  | run 進行中指示線是 chat column grid 的獨立一列，畫在 footer slot 之前。不要把它搬回 `ChatbotFooter`；`RunningIndicator` 也不匯出。自訂 `renderFooter` 的消費端不要再畫自己的上緣分隔線 | 刻意的行為            | 它綁的是整條連線的狀態；放在 footer 裡會被 `renderFooter` 一起換掉（heimdall-pm#200）。指示線在所有 footer 路徑上都已出現，消費端不需要自己掛；消費端自己再畫一條分隔線，會和它疊成雙線 | 原 BUILD-034             |
| CONVO-8  | 所有 spinner 共用同一個相位：用 Web Animations API 並把 `startTime` 釘在 0。不要用 CSS animation，也不要在元件裡自己寫 spin `@keyframes`                                               | 刻意的行為            | CSS animation 從各自掛載的那一刻起算，沒有共同的時間原點；滿畫面不同相位的 spinner 看起來像在扭動（BUG-007）                                                                            | 原 BUILD-050             |
| CONVO-9  | `prefers-reduced-motion` 時所有 spinner 一律停轉，包括原本只是減速的 chat header                                                                                                       | 理由                  | BUG-007〈修復方向〉只是參考解；統一停轉是計畫階段向使用者確認過的取捨（見 CONVO-26）                                                                                                    | 原 BUILD-050、REVIEW-050 |
| CONVO-13 | 已終態的 subagent 再收到 `subagentStart` 或子 tool-call 的 `toolStart`，狀態回到 `running`，並清掉上一次的 `summary`。不要把狀態改回「只會收斂」                                       | 刻意的行為            | 有新活動就是又在跑；跨 turn 恢復時後端不發任何 lifecycle event，只看得到子 tool-call。消費端因此不能把「出現終態」當成一次性事件                                                        | 原 BUILD-041             |
| CONVO-15 | subagent 的子 tool-call 結果原樣交出，不截斷、不遮蔽；欄位名跟 `ConversationToolCallMessage` 一致（`result`／`sidecar`），不跟 wire 名                                                 | 理由                  | 遮蔽與截斷已裁決歸呈現端；同一個值在兩個 SDK 型別上叫兩個名字，會讓人以為是兩種東西                                                                                                     | 原 BUILD-083             |
| CONVO-36 | 使用者泡泡的 `max-width: 75%` 留在 `.text--user`；機器人那邊的寬度則放在 `.text--bot-default`。兩邊刻意不對稱，不要「對齊」                                                            | 刻意的行為            | 機器人的上限移出去，是為了讓自組的機器人列填滿閱讀寬度；使用者那邊的 75% 是泡泡外觀的一部分，自組的使用者列也該是泡泡。要改寬度用 `className`                                           | 原 BUILD-042             |

## 已知限制

| 編號     | 限制                                                          | 原因                                                                                                                                               | 待誰處理 |
| -------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| CONVO-27 | 重播出的 tool-call 時間是「現在」，不是原始時間               | 跨 rejoin 以 `time` 排序不準；畫面依串流順序與 `${processId}-${callSeq}` 排列，目前看不出差異；需要依時間排序時再處理                              | 不處理   |
| CONVO-28 | 跨 turn 恢復的 subagent 結束後不會回到終態                    | 後端在跨 turn 恢復全程不發 lifecycle event，包括結束時的 `subagent.complete`，卡片在那個 turn 之後一直顯示 running                                 | 後端     |
| CONVO-29 | 冷啟動重播出的 subagent 卡片缺資料                            | 重播不含 subagent lifecycle event，只由子 tool-call 重建的卡片沒有 `subagentType`／`description`，而且一直顯示 running；history 要帶什麼由後端決定 | 後端     |
| CONVO-31 | 自組訊息列不帶 `asgard-text-template--user` class             | 那是 `TextTemplate` 自己掛的 global class，`BotMessageText` 也一樣；消費端要對它下樣式得自己掛                                                     | 不處理   |
| CONVO-35 | 未驗證：tool-call 群組與檔案總管的 spinner 沒有在瀏覽器實測過 | 兩者的 loading 在 demo 裡是瞬時的；依據是樣式原文核對、型別檢查與測試；補驗需要一個能停在 pending 的 demo 路由                                     | 需另立票 |
