# 多語系

## 範圍

- 涵蓋：`@asgard-js/react` 內建的三語文案目錄，以及 `<Chatbot locale>` 怎麼傳到每一個內建元件（含檔案總管與 `authState` 不是 `authenticated` 時的畫面）。
- PM 規格：[F-005 tool-call i18n locale prop](../../references/asgard-sdk-pm/tracking/asgard-js-sdk/features/F-005-tool-call-i18n-locale-prop.md)；其餘來源是 [sdk-pm#49](https://github.com/asgard-ai-platform/asgard-sdk-pm/issues/49) 與本 repo 的 issue #387、#388、#391。
- 優先順序：產品規則以 PM 規格為準，實際行為以程式為準；本章只記兩者都讀不出來的決定、差異與限制。

## 設計決定

| 編號   | 決定                                                                                        | 類型       | 為什麼                                                                                                                                                                 | 出處         |
| ------ | ------------------------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| I18N-4 | template context provider 只有一個，包在整個 container 外層。不要讓檔案總管側欄自己再包一層 | 刻意的行為 | 側欄為了讓 header 與 composer 一起收窄，被放成 chat column 的兄弟節點，因此落在原本 provider 之外。上移後 provider 的每個 prop 在新位置都已在 scope 內，也避免重複巢狀 | 原 BUILD-043 |
| I18N-5 | 檔案總管原始碼（不含測試）不放任何 CJK 字面值，由測試掃描把關                               | 刻意的行為 | 以「零 CJK 字面值」驗收，不受字串寫法影響；原本「換掉 56 個字串」的計數就漏了一個 JSX 文字節點                                                                         | 原 BUILD-038 |
| I18N-6 | `authState` 不是 `authenticated` 時的畫面，由 `<Chatbot>` 直接傳 `locale` prop（沒傳時用 `en-US`）；`ApiKeyInput` 只在沒收到 `locale` prop 時才讀 template context   | 理由       | 那條路刻意不建立 service provider（避免開 SSE），也就沒有 template context；原本一半文案由外部預先翻好、一半讀 context，接線分成兩半而永遠拿到 `en-US`                 | 原 BUILD-045 |

## 已知限制

| 編號    | 限制                                                | 原因                                                                                                                                                                                           | 待誰處理 |
| ------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| I18N-9  | 未驗證：`authState` 不是 `authenticated` 時的畫面沒有在瀏覽器實際走過  | 要渲染那些狀態需要處於對應狀態的 bot provider，本機 demo 沒有；目前的保證來自單元測試；取得 private bot 憑證時補驗                                                                             | 需另立票 |
| I18N-10 | 未驗證：ja-JP／zh-TW 的檔案總管沒有在瀏覽器實際走過 | 目前只靠測試與目錄一致性保證。demo `/file-explorer` 的獨立面板幾段有語系切換；同一路由裡內建側欄與 Nudge 的 `<Chatbot>` 沒有跟著語系（內建側欄寫死 `zh-TW`），補驗內建側欄的 ja-JP 要先改 demo | 需另立票 |
| I18N-11 | `ApiKeyInput` 的頭像仍讀 service context            | `authState` 不是 `authenticated` 時，元件樹沒有 service provider，所以它一直拿 context 的預設值；與 I18N-6 同一類問題                                                                                                           | 需另立票 |
| I18N-12 | 字面值掃描對極短的文案可能誤判                     | `chatbot-i18n.spec.tsx` 檢查 `MIGRATED_WORDING` 裡每一句舊英文文案有沒有以引號字面值或 JSX 文字節點出現在 chatbot 原始碼；文案很短時（例如 `Key`）可能和不相關的字面值相同而誤報                                                                                                                                         | 不處理   |
