## 現行行為

| 編號   | 項目                 | 現行行為                                                                                                                                                                                                                                                           |
| ------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| I18N-1 | 語言與目錄           | 支援 `en-US`、`ja-JP`、`zh-TW`（型別 `Locale`）。所有內建文案都在 `i18n.ts` 的三語目錄裡，經 `t(locale, key, vars)` 取得；每個 key 三種語言都有、插值參數一致，由目錄一致性測試把關。                                                                              |
| I18N-2 | fallback             | 找不到 key 或語言時退回 `en-US`，`en-US` 也沒有才回傳 key 本身；這條路不能被繞過。                                                                                                                                                                                 |
| I18N-3 | `locale` 的預設      | `<Chatbot>` 沒傳 `locale` 時，所有文案都是 `en-US`。（`locale` prop 本身的規格待驗收：BUILD-007）                                                                                                                                                                  |
| I18N-4 | 一個 provider 包全部 | `AsgardTemplateContextProvider` 包在 `ChatbotContainer` 外層，樹裡只有一個。chat column、內建檔案總管側欄、header 的檔案總管開關（`aria-label`／`title`）、拖放覆蓋層都在它底下，所以 `<Chatbot locale="zh-TW">` 會讓它們全部變成中文，consumer 不必再自己包一層。 |
| I18N-5 | 檔案總管             | 內建檔案總管的所有文案從 `useAsgardTemplateContext()` 取得語言，沒有新的 prop；`file-explorer/` 原始碼（不含測試）裡沒有任何 CJK 字面值，載入失敗列也是在地化文案。                                                                                                |
| I18N-6 | 驗證畫面與錯誤狀態   | 未驗證狀態（`needApiKey`、`invalidApiKey`）與錯誤狀態（`error`、`subscriptionExpired`、`botNotFound`）的文案都走目錄。這條路刻意不建立 service provider（避免開 SSE），也沒有 template context，所以 `<Chatbot>` 直接把 `locale` 傳給這些元件。                    |
| I18N-7 | API key 畫面         | `ApiKeyInput` 收 `locale` prop：欄位標籤、placeholder、顯示／隱藏密碼的 `aria-label`、送出鈕（含載入中）、無效金鑰訊息全部以同一個語言呈現。單獨使用、沒傳 `locale` 時退回 template context 的語言。                                                               |
| I18N-8 | 拖放提示             | 把檔案拖到 chatbot 上時的提示（`Drop files here`）走目錄。                                                                                                                                                                                                         |

## 設計決定

| 決定                                                                           | 理由                                                                                                                                                                           | 出處         |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------ |
| 把 template context provider 上移到包住整個 container，不讓 aside 自己再包一層 | 檔案總管側欄為了讓 header 與 composer 一起收窄，被放成 chat column 的兄弟節點，因此落在原本 provider 之外。上移後 provider 的每個 prop 在新位置都已在 scope 內，也避免重複巢狀 | 原 BUILD-043 |
| 未驗證路徑的元件用 `locale` prop，context 只當 fallback                        | 那條路沒有 template context；原本 `placeholder`／`error` 由外部預先翻好、其他字讀 context，接線分成兩半而永遠拿到 `en-US`。改成只傳一次 `locale`                               | 原 BUILD-045 |
| 以「原始碼裡零 CJK 字面值」驗收，而不是「換掉 56 個字串」                      | 第一次的計數漏了一個 JSX 文字節點（實際是四個檔共 57 個）；零 CJK 的檢查不受字串寫法影響                                                                                       | 原 BUILD-038 |

## 已知限制與未交付

| 項目                                      | 說明                                                                                                                                                                | 交接                      |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 驗證狀態畫面沒有在瀏覽器實際走過          | 要渲染 `needApiKey`／`subscriptionExpired`／`botNotFound` 需要處於對應狀態的 bot provider，本機 demo 沒有；目前的保證來自單元測試（key 解析、用字鎖定、字面值掃描） | 取得 private bot 憑證時補 |
| ja-JP／zh-TW 的檔案總管沒有瀏覽器層級驗證 | 由測試與目錄一致性保證                                                                                                                                              | —                         |
| `ApiKeyInput` 的頭像仍讀 service context  | 未驗證路徑沒有 service provider，所以它一直拿 context 的預設值；與 I18N-6 同一類問題                                                                                | 需另立票                  |
| 字面值掃描對極短的 key 可能誤判           | 掃描只比對引號字面值與 JSX 文字節點；之後加入極短的 key 要留意                                                                                                      | —                         |
